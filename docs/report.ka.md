## 1. აღმასრულებელი რეზიუმე

მიმდინარე CASCO პორტფელი **მუშაობს თავისი სამიზნე ზარალიანობის ზემოთ**. **119,745** პოლისის განმავლობაში პორტფელი აჩვენებს:

| მეტრიკა | მნიშვნელობა |
|---|---|
| დაგროვილი პრემია | **GEL 172.4M** |
| ინკური ზარალი | **GEL 121.7M** |
| **პორტფელის ზარალიანობა** | **70.6%** |
| მთლიანი მოზიდული (ბრუტო) პრემია | GEL 223.8M |
| დაზღვეული თანხა (GEL) | GEL 5.49B |
| პოლისის რეითი (GWP / დაზღვეული) | 4.07% |
| ზარალის სიხშირე | 0.66 ზარალი / პოლისი |
| ზარალის სიმძიმე | GEL 1,546 |

**სამიზნე ზარალიანობის 60%**-ით, პორტფელი ნაკლებად ფასდება საშუალოდ
**+18%**-ით (`0.706 / 0.60 − 1`). ფასის არასწორება არ არის ერთგვაროვანი — ის
კონცენტრირდება კონკრეტულ რისკის სეგმენტებში, რაც სწორედ ის ადგილია,
სადაც ტარიფის ქმედება უნდა მიღებულ იქნეს.

**მთავარი აღმოჩენები**

* **უფრო ახალგაზრდა მძღოლები არიან ყველაზე ცხელი სეგმენტი.** ასაკი 21–29 რბენენ ზარალიანობას
  **87–89%** წინააღმდეგ **63%**-ისა მძღოლებისთვის 40-ზე უფროსის, მიუხედავად იმისა, რომ ისინი უკვე იხდიან
  საშუალოდ ორჯერ უფრო მეტ პოლის-თითო რეითს.
* **ფრანშიზის გარეშე (franchise = No) პოლისები არიან არსებით უფრო ცუდი** (ზარალიანობა
  **74.3%**) ვიდრე ფრანშიზიანი პოლისები (**55.5%**), მაგრამ ორივეს აქვთ ერთი და იგივე
  საშუალო რეითი (4.97%).
* **დაბალი დაზღვეული თანხის მქონე ავტომობილები ნაკლებად ფასდებიან.** ზარალიანობა ერთგვაროვნად ეცემა
  ~0.75–0.85-დან ყველაზე პატარა კალათებში **48%**-მდე USD 50k-ზე, ხოლო პოლისის
  რეითიც *კლებულობს* დაზღვეულ თანხასთან — რისკის მიუთითებელ პირიქითი.
* **მაღალი გამავლობის (SUV-ტიპის) ავტომობილები** დომინირებენ მოცულობას (68k პოლისი) და რბენ
  **67%** ზარალიანობით; **სედანები** (50k პოლისი) რბენ **78%**-ით.

კონვეიერი აწარმოებს სრულ ფასის-კორექციის ცხრილს (± შეზღუდული 50%-ზე, შეკუმშული
კრედიბილურობით) **1,264 კომპოზიტური სეგმენტისთვის** — იხილეთ `output/`.

## 2. Data & methodology

### 2.1 წყაროები (`data/`-ში)

| ფაილი | როლი | მთავარი შეერთება |
|---|---|---|
| `Policies_1805_v4.csv` | პოლისთა მასტერი (128k რიგი) | `policyid` |
| `Claims_1805_v2.csv` | ზარალები (98k რიგი) | `policyid` |
| `Clients_1805_v3.csv` | კლიენტთა მასტერი (55k რიგი) | `clientid` |
| `enrcols.csv` | პოლისთა გამდიდრება (Casco/MTPL/MPA ჯვარეთქტური) | `id` = `policyid` |
| `fx_rates.csv` | ყოველდღიური GEL/USD (2.7k რიგი) | as-of `efdate` |
| `franchise_field_categories.csv` | გამოკლების-კატეგორიის ძებნარი | `resolved_value` |

### 2.2 გაწმენდა და ფილტრაცია (`src/load_data.py`)

1. **მხოლოდ CASCO** — შეინახე ის პოლისები, სადაც `licensename` შეიცავს "casco"-ს.
2. **მხოლოდ ფიზიკური კლიენტები** — შეინახე `clientstatus`, რომელიც შეიცავს "ფიზიკურ"-ს
   (ინდივიდუალური/ფიზიკური).
3. **მხოლოდ პირადი გამოყენება** — შეინახე `enrcols.გამოყენება` (გამოყენება), რომელიც შეიცავს "პირად"-ს
   (პირადი).
4. **მხოლოდ ვალიდური ზარალები** — `calcclaimstatus` ∈ {"Easy Settlement",
   "Hard Settlement"}; ინკური ზარალი = `reportedclaimamount`-ის ჯამი.
5. **FX ნორმალიზაცია** — `suminsured_usd = suminsuredgel / gel_per_usd` უკანმიმართული
   `merge_asof`-ით პოლისის ძალმოქმედების თარიღზე, რათა ყოველ პოლისს ჰქვს FX კურსი,
   რომელიც მოქმედებდა მის დაწყებისას.
6. **ფრანშიზის (გამოკლების) გადაწყვეტა** — იმპლემენტირებულია ზუსტად პროექტის
   README-ის მიხედვით: გადაწყვიტე გამოკლების ველი `ფრანშიზის ველი`-დან → `ფრანშიზა` →
   `არასტანდარტული ფრანში`, გადაიყვანე გადაწყვეტილი მნიშვნელობა `deductible_category`-ზე
   `franchise_field_categories.csv`-ის გამოყენებით და მონიშნე პოლისი
   `deductible_type = "No"`-ით, როცა კატეგორია არის ნულოვანი/არა-გამოკლების კლასი,
   წინააღმდეგ — `"Yes"`.

### 2.3 რისკის სეგმენტაცია (`src/segments.py`)

ოთხი რეითინგის განზომილება, README-ის ფრაგმენტების ზუსტი გადმოტანით:

* **კლიენტის ასაკი** → სარტყები `18-20`, `21-25`, `26-29`, `30-40`¹, `>40`.
* **ავტომობილის ტიპი** → შეკუმშვა README-ის `.replace()` რუქით
  *სედანი / მაღალი გამავლობის / კუპე-კაბრიოლეთი*-ში (დარჩენილი იშვიათი ტიპები შენარჩუნებულია).
* **ფრანშიზა** → `deductible_type` ("Yes" / "No").
* **დაზღვეული თანხა (USD)** → README-ის `pd.cut` კალათები (`SI<=5k`, `6k<SI<=7k`, …,
  `>50k`).

¹ README ფურჩებს `18-20, 21-25, 26-29, >40`; `30-40` სარტყი დაემატა, რათა
30–40 ასაკის დიაპაზონი არ იქნეს ჩუმად გამოტოვებული (`>40` სტრიქტულად მეტია 40-ზე).

### 2.4 მეტრიკები (`src/metrics.py`)

* **ზარალიანობა** = ინკური ზარალი / დაგროვილი პრემია
* **პოლისის რეითი** = გრული ჩაწერილი პრემია / დაზღვეული თანხა
* **სიხშირე** = ზარალები / პოლისები; **სიმძიმე** = ინკური / ზარალები
* სეგმენტ-თითო აგრეგატები იქმნება კომპოზიტური სეგმენტისთვის და თითოეული
  ერთი განზომილებისა და მთავარი ორმხრივი კვეთებისთვის.

### 2.5 რეკომენდაციები (`src/recommend.py`)

ყოველი სეგმენტისთვის:

```
raw_correction        = (loss_ratio / target_loss_ratio) - 1
credibility           = min(1, earned_premium / full_credibility_premium)
recommended_correction = clip(raw_correction * credibility, -0.50, +0.50)
recommended_rate       = current_policy_rate * (1 + recommended_correction)
```

ნაგულისხმევი: `target_loss_ratio = 0.60`, `full_credibility_premium = GEL 5M`,
`max_correction = ±50%`. კრედიბილურობა შემცირებს კორექციებს თხელი სეგმენტებისთვის, რათა
ვერ გადავიმედოთ ხმაურიან ზარალიანობებზე.

## 5. რეკომენდაციები

სრული კორექციების ცხრილი მდებარეობს `output/segment_recommendations.csv`-ში (1,264

## 9. გაფართოებული სტატისტიკური მოდელები (ნაწილი B)

ნაწილი A (სექციები 1–8) არის **სეგმენტის / გამოცდილებით-რეიტინგის** ხედი. ნაწილი B აშენებს
**ინდივიდუალური რისკის სტატისტიკურ მოდელებს** იგივე გაწმენდილ ჩარჩოზე, ვალიდირებს მათ
**დროით გარეთ** (არ არის შემთხვევითი გაყოფა — ტრენინგი `efdate < 2025-01-01`, ტესტი
`efdate >= 2025-01-01`), და წარმოადგენს მოდელზე დაფუძნებულ რეითის ინდიკაციას
ელასტიურობითა და მონიტორინგის დაფას.

### 9.1 მეთოდოლოგია

* **დროზე დაფუძნებული გაყოფა** (`src/features.py`) — თავიდან იცილებს გაჟონვას; ტესტის ფანჯარა არის
  უახლესი 12+ თვე. ტრენინგი (ექსპოზიცია > 0): **87,961** პოლისი;
  ტესტი: **31,764**. ზარალის მქონე ტრენინგი: **37,082**; ზარალის მქონე ტესტი: **10,572**.
* **სიხშირე** (`src/frequency.py`) — მოსალოდნელი ზარალის რაოდენობა პოლისზე.
  Poisson-ისა და Negative-Binomial GLM-ები `offset = log(earned_premium)`-ით;
  LightGBM Poisson GBM (`log_exposure` ფიჩერით, რათა იგივე ექსპოზიციის
  ნორმალიზაცია ჰქონდეს, რაც GLM-ებს). **ოფსეტი ხელახლა გამოიყენება პროგნოზის
  დროს** — GLM, რომელიც ოფსეტით არის მორგებული, მაგრამ ოფსეტის გარეშე შეფასებული
  ექსპოზიციას აჩვენებს, არა მოსალოდნელ რაოდენობას.
* **სიმძიმე** (`src/severity.py`) — ზარალის თანხა *პირობითი დადებით
  გადახდაზე* (ნულოვანი გადახდის ზარალები უკვე ჩათვლილია სიხშირით). LogNormal
  GLM (Gaussian `log(amount)`-ზე) და LightGBM Gamma GBM. **Gamma GLM
  მოიხსნა** — `statsmodels` IRLS/bfgs იშლება ამ მძიმედ-კუდიან სამიზნეზე
  (თავთაბარი იფეთქებს ან ინვერსიულად-რანჟირებულ ლოკალურ ოპტიმუმში ეცემა).
* **სუფთა პრემია** (`src/pure_premium.py`) — `E[cost] = E[N]·E[S]`:
  მრავლობითი Poisson×LogNormal მოდელი **და** პირდაპირი Tweedie (ძალა 1.5)
  LightGBM `incurred_claim`-ზე (ნულოვანი მასა + უწყვეტი კუდი).
* **კრედიბილურობა** (`src/credibility.py`) — Bühlmann-Straub შემცირებს თითოეულს
  სეგმენტის დაკვირვებულ სუფთა პრემიას პორტფელის საშუალოსკენ
  `Z_i = n_i / (n_i + k)`, `k = EPV/VPP`, სადაც `n_i` = **პოლისების რაოდენობა** (არა
  დოლარის ექსპოზიცია, რაც ყველა სეგმენტს სრულად კრედიბილურს გახდის).
* **ტარიფიკაცია** (`src/pricing.py`) — ტექნიკური პრემია = `model_pp / target_LR`,
  რეითის ცვლილება შეზღუდულია ±50%-ით, ელასტიურობაზე დაფუძნებული მოცულობის რეაქცია.
  **კალიბრაციის ფაქტორი** (საშუალო ფაქტიკური ÷ საშუალო პროგნოზირებული დოლარი) ასწორებს
  მრავლობითი მოდელის დონეს ინდიკაციამდე.
* **ვალიდაცია** (`src/validation.py`) — ყოველთვიური ფაქტიკური-საპირისპირო-პროგნოზირებული ზარალიანობის
  მონიტორინგი hold-out-ზე, პლუს დროით გარეთ სადაზღვევო Gini.

**სადაზღვევო Gini** (რანჟირების მეტრიკა, გამოიყენება მთელს მანძილზე): Lorenz / accuracy-ratio
ფორმა — პოლისები დალაგებული პროგნოზირებული რისკის მიხედვით (ასვლით), `Gini = 1 − 2·(ფართობი
კუმულატიურ-ზარალის Lorenz მრუდის ქვეშ)`. შეზღუდული, რანჟირებაზე დაფუძნებული და სტაბილური კიდეც
მძიმედ-კუდიანი სიმძიმისთვის (განსხვავებით კოვარიაციის ფორმისგან, რომელიც დისპერსიით მასშტაბდება).
0 = დისკრიმინაცია არ არის; უფრო მაღალი = უკეთესი.
